## 2026-10-03 小米 15 无线 adb 重新连上 + FP16/EP 探测（详见 `notes/20261003_fp16-xiaomi15.md`）


**连法**：`adb connect 192.168.1.87:43565`（序列号就是 `192.168.1.87:43565`，每次端口会变）。
这台是 `2410DPN6CC` / SM8750 / **Android 16(API 36)** / 8 核（6@2227200kHz）。
`install -r` **没清 a11y**（前后都是那三条 enabled_accessibility_services）；游戏 `com.miHoYo.Yuanshen` 装着。

**FP16 的实测答案：开不出收益，别开。**
- 新入口 `-a com.bettergi.pocket.action.DEBUG_OCR_EP --ez risky true|false`：**另建一份一次性引擎**
  跑 det/rec 基准后 close，不动生产档位（`OcrFactory.epProbe`）。此前 `EpTierPicker` 注释里的
  `ocrEp=risky` **根本不存在** ⇒ `NN_API_FLAGS` 里的 `USE_FP16` 在任何机型上都没真跑过。
- 同进程 A/B/A/B（各 5 次中位）：**det CPU 50ms → NNAPI 545ms（≈10.8× 慢，复现 3 次）**；
  rec w=320 打平 4ms、w=684 反而 9→13ms。**头一分钟两边都是冷读数**（CPU 自己 110→50），
  只看头一次会得出完全错误的结论。
- 这台机器**没有厂商 NNAPI 驱动**（`lshal` 全表无 `neuralnetworks`、VINTF 未声明、`/vendor/lib64` 无 SLDR 库），
  但 **NNAPI 客户端库在 APEX 里且对应用可见**：`/apex/com.android.neuralnetworks/lib64/libneuralnetworks.so`，
  `ld.config.txt` 的 `namespace.default.link.com_android_neuralnetworks.shared_libs` 含它
  ⇒ ORT 的 NNAPI EP dlopen 得到的就是它，跑的是 APEX 自带的 CPU 参考实现。
  ⚠️ **别只查 `/system/lib64/libneuralnetworks.so` 就下"Android 16 删了 NNAPI"的结论** —— 我这次差点误判，
  `ls /apex` 对 shell 是 `Permission denied`，但**直接写全路径能读到**。
- BlueStacks / 华为 P20 上 `addNnapi` 原生 SIGSEGV 的旧账在这台**没复现**（三次探测进程全程活着）。

**`soc=unknown` 是判据 bug，不是机器问题（已修）**：小米 15 的 `ro.soc.manufacturer` 是 **`QTI`** 而不是
`Qualcomm`，而 `readSoc()` 只要该字段非空且 != unknown 就直接归一、不走 `ro.hardware` 回退 ⇒
`normalizeVendor` 返回 unknown ⇒ `probeQnnLibs()` **提前 return false**（连 loadLibrary 都没试）、
`EpTierPicker` 的 QNN 双闸第一闸永不过 ⇒ 日志里的 `qnn=false` 分不清"库没公开"与"厂商没认出来"。
修 = 认 `"qti"`（精确等值）+ 提 internal + `DeviceCapabilitiesVendorTest`。
修完剩下的 `qnn=false` 才真正只表示 (b)：**QAIRT 库在 `/odm/lib64` 且不在任何 public.libraries*.txt**
（那四份只公开 `libSNPE/libcdsprpc/libmiocr` 等）⇒ 上 HTP 必须自己捆库 + 换 ORT flavor。
顺带：`libmiocr.so` 是**公开的**（小米自带 OCR），本次没探。

**intra-op 在这台第一次量到 6 或 4**（`2=9ms,4=5ms,6=4ms` / `2=10ms,4=6ms,6=5ms`）
⇒ 与 Kirin 970 的"2 最优"方向相反；#74 的"实测优先 + 20% 余量"是对的口径，但别把 2 当普适值。


## 悬浮窗（overlay）真机对拍（2026-10-01 18:19–18:29，2244 档）


**"广播被静默丢弃"有第二种成因**，症状与 `Background execution not allowed` 一模一样（`result=0` + 零日志）：
`DEBUG_DUMP_GOOD` / `DEBUG_SET_GOOD` **根本不在** `DebugControlReceiver` 的 action 表里（该表只有 9 条
`com.bettergi.pocket.debug.*`）。⇒ 判"是权限问题还是我发错了 action"之前先数 action 表；正确姿势是直接对
service 发 `com.bettergi.pocket.action.*`。同日 `am broadcast …debug.STATUS -n …/.debug.DebugControlReceiver`
是**通的**（日志立刻出 `status …`）⇒ 别把 receiver 整条路当死了。

**overlay 只能像素级定位**：`uiautomator dump` 在原神前台只出 1754 字节、且**不含我们自己的 overlay 窗口**
（它 dump 的是 focused window）。⇒ 量 UI 用 `screencap` + 系统 python3/PIL 纯循环按颜色分类，别指望 AX。

⚠️ **`uiautomator dump` 会把展开态悬浮面板收起**（2026-10-03 实测：展开 → dump → 再读 `dumpsys window`
已是 72×72）。所以任何"面板帧 + 视图树"同时需要的断言，**必须先读 dumpsys 帧、再 dump UI**；
反过来的话重叠/遮挡类断言会拿收起态的帧去判，**前提没成立却报绿**（我第一版 `manager-collision` 就这么空跑过）。

2244 档可复用坐标（1:1，`screencap` 就是 2244×1080）：悬浮球默认中心 **(2196,244)** ⌀≈68；
头部三钮 y=82、x 依次 **2055 B站主页**（点了会跳外部浏览器，别碰）/ **2120 识别日志 toggle** /
**2190 收起 ✕**；日志窗自身 ✕ **(383,779)**。

三条判据：① **悬浮球可见 ⇒ 面板已收起**（展开时 bubble 被 GONE），比"数暗像素"可靠得多——夜间游戏背景本身就很暗；
② 拖动**只沿右缘纵移**（09-14 用户定稿）：`swipe 2196,244 → 1400,900` 实测 x 中心 2196→2197（横向 −796px 被 clamp 吃掉）、
y 跟手到 901 ⇒ 想验 clamp 必须**故意带一个大的横向分量**，纯纵向拖测不出约束；
③ 面板「页数」徽标**金色且带数字 = 非默认**（默认 0 只显示"页数"弱色），而悬浮窗 ▶ 走
`maxPagesOrDefault(settings.scanMaxPages)` ⇒ 徽标是 `页数 1` 时从 UI 起跑只会扫 1 页（≈21 件）。
**跑 UI 入口前先读这个徽标**，"整轮只跑了三页"这类现象先查它。

拉起悬浮窗的入口只有 `ACTION_START`（`overlayController.show()` 挂在它上面）；
`am start-foreground-service -n …/.service.TriggerForegroundService -a com.bettergi.pocket.action.START`。

⚠️ **`DEBUG_STATUS` 里的 `scan=` 是"扫描开关"，不是"有没有流程在跑"**（2026-10-01 踩）：
用 `DEBUG_SCAN_FLOW` 起的跑不会翻这个位 ⇒ 拿 `scan=false` 当"跑完了"的轮询信号会**提前退出**
（实测一轮 93 角色的 character_scan，第 4 分钟就被我判成结束，其实才走到 36/93）。
正确的完成判据是日志 `BetterGI.Scan: scan finished: … elapsed=… cells=… pages=…` 或 `导出完成`；
`scan finished: stopWhen` 对 character_scan 是**正常收尾**（名册到底 ⇒ 连续重复页停），别当故障。
★ 同一条性质反过来也成立（2026-10-03）：**凡是门控在 `scanEnabled` 上的分支，都不能用
`DEBUG_SCAN_FLOW` 去测** —— 它不翻这个位，被测分支根本不会被走到。要测就先
`-a …DEBUG_SET_SCAN --ez enabled true`（配合 `DEBUG_SET_MAX_PAGES --ei pages N` 限页），
这才是"从开关起扫"的那条产线路径。

两条顺带量到的：① 页数上限有干净的写入口 `-a …DEBUG_SET_MAX_PAGES --ei pages 0`（0=无限），
不必去点面板那行输入；② `DEBUG_SET_NAME_OVERRIDE` **不给 `--es value` 就是把那一格清空**
（`getStringExtra` 返回 null ⇒ `withField(field, null)`），探当前表值只能"写一次 + 看回读日志"，
日志会打整张 `NameOverrides(...)`。


## 2026-10-02 华为真机（VED0218912000022，2244 档）本轮新增实锤


**刷 GT 的顺序在华为上是硬的**：必须先把游戏 `force-stop`、重启到**标题屏**，**然后**才 `CAPTURE_START`，
最后点「点击进入」。反序（先起抓包、游戏还在世界里）时握手就发生在抓包开始那一刻，之后冷启动
**不再产生新的 handshake**（整份日志只有开头一次 `handshake requested` + `found initial decryption key`），
然后一直 `Couldn't deduce the session key` / `Unable to find the encryption key seed`，白等十几分钟。
正确顺序：`found initial decryption key` → `setting new possible session seeds` →
`matched achievement packet` → `入库（四段数据齐）`，实测 09:41:58 起、09:42:07 入库，**约 10 秒**。

**华为的 VPN 授权弹窗**：标题是「连接请求」（`com.android.vpndialogs`），「确定」bounds `[1589,833][1781,977]`
⇒ 中心 **(1685,905)**，「取消」在左。**第二次起记住授权、不再弹**（`ip -o addr` 里出现
`tun0 10.215.173.1/30` 即已授权）。判"隧道在不在"看 `tun0` 接口，**不看 `DEBUG_STATUS`**。

**`install -r` 这次没有清掉 a11y**（与上面"华为四条坑①"矛盾）：装完 `settings get secure
enabled_accessibility_services` 仍是 `com.bettergi.pocket/.input.InputAccessibilityService`。
⇒ 把那条"必被清"改成"**可能**被清"：装完一律 `settings get` 复查，别当已验证前提。

**`artifact_lock` 不注入 plan = 纯读、零改动**：日志打 `planMatch: plan 为空 ⇒ 跳过` +
`ifMatch: no plan injected (vars.currentTask null), then skipped` + `stopWhen triggered (page): planRemaining == 0`
⇒ 只是把列表走一遍、**不点任何加/解锁按钮**，账号锁态无变化（可安全跑，无需先问）。

**华为 logcat 环形缓冲很小且被帧流冲掉**：`logcat -d` 全量会**超时挂起**，`logcat -d -s Tag:V` 也常只剩
`--------- beginning of main`（`logcat -G 16M` 也救不回）。可靠做法是**设备端落盘**：
`adb shell "nohup logcat -v threadtime > /sdcard/xxx.txt 2>&1 &"`，**每轮开跑前先
`pkill -f 'logcat -v threadtime'`**（否则上一轮的进程继续写进同一文件，见
[[feedback-file-writes-and-stray-captures]]），再 `logcat -c` + `rm -f` 旧文件。

**扫描起跑前游戏必须在世界主界面**：上一轮扫描/探针跑完会把游戏留在背包页或角色属性页，此时再发
`SCAN_FLOW` 会立刻 `returnHomeStuck`（`returnToHome: 点击后画面无变化 ⇒ 判定无进展，停手`）。
回主界面靠 `input keyevent KEYCODE_BACK`，但**连按 4 次会弹「确认退出游戏」**（我踩过）——
只能点「取消」（红线：绝不替用户退出游戏），且该点击坐标要按**全分辨率**量（按半尺寸缩略图点错过一次）。
判"在世界里"最省事的仍是起跑日志的 `returnToHome: 已在主界面` 或 `frame acquired 2244x1080`。

**`scan finished: watchdog` 是真机 OCR 慢触发的单页看门狗**，不是缺陷：单页 114s 超时即收，
摘要 `cells=19 pages=1`、`ocr avg≈1.2s`。别当故障去查。

## 2026-10-02 下午（#169 三版五轮）新加的四条硬事实


1. **`recover_bs.sh` 装的是"当下那个 APK"** —— 改完代码只跑测试门就直接 `recover_bs.sh`，装的是**上一版**，
   日志会看着像"我的改动没效果"（我 14:47 那轮就是这么白跑的：新代码在 14:40 的测试门里过了，但没
   `assembleDebug`）。⇒ 设备验证前的固定顺序：**`assembleDebug` → 再 `recover_bs.sh`**；
   要证"改动进了产物"就按 UTF-8 字节在 dex 里搜自己新加的中文串（`grep -alc '串' *.dex`），
   `strings` 看不见多字节、APK 字节数两次相同也不代表产物相同。
2. **MediaProjection 弹窗这次会"看着弹了其实没授权"**：`requesting media projection permission` 之后
   若 60s 内没人应答，日志打 `BetterGI.Service: capture consent 无人应答（60000ms）⇒ 复位发起标志`，
   此时 `input tap 1374 722` 是**点晚了/点在已关的窗上**。硬判据用
   `dumpsys media_projection | grep com.bettergi.pocket`（有 = 真持有），弹窗在否用
   `uiautomator dump` 查 `立即开始` 的 bounds（该弹窗**能出完整 bounds**，与原神前台 dump 只 1754 字节不同）。
   重发起：`DEBUG_SET_SCREEN_SHARE --ez enabled false` → 2s → `--ez enabled true` → 再点 (1374,722)。
   ⚠️ BlueStacks 有时**自动放行**（`recover_bs.sh` 后 15s 就 `first frame acquired`），别把"没弹窗"当失败。
3. **要抓"某一份日志里某一页当时的画面"：设备端自触发 `screencap`**（比宿主轮询可靠）：

## 2026-10-06 管道 A/B 这一轮新增三条


1. ⚠️ **发完 `DEBUG_SCAN_FLOW` 必须先确认它真起跑，再开始任何计时/采样**：投影没在跑时服务只打一行
   `scan flow request ignored: projection not running` 就**什么都不做**（不报错、不退出、退出码 0）。
   我因此连着两轮在**空闲设备**上采了十几分钟 `top -H` 与逐线程 CPU，读数全 0.0% 还差点归因成
   "抓帧线程泄漏吃 2 个核"。判据：发指令后 20s 内 `logcat -d -s BetterGI.Scan:*` 要出 `timing:`；
   没有就去 grep `ignored`。同理 `DEBUG_SET_SCREEN_SHARE false→true` 之后**也要重读 `frame acquired`**
   才算开成（本轮它"再开一次"静默失败过两次）。
2. **`top -H -b -n1` 不能用来判"谁在吃 CPU"**：它按 **TID（创建序）**列而不是按 %CPU 排序，且
   `TIME+` 是**线程自创建以来的累计值** —— 一个冻住不动的 `2:19` 是历史，不是当前负载。
   要瞬时归属就自己算：`/proc/<pid>/stat` 的 `$14+$15`（utime+stime，USER_HZ=100）取差值得进程 CPU 秒。
   ⚠️ `pidof com.bettergi.pocket` **匹配不到 `:a11y` 子进程**（进程名带后缀），`ps -A | grep bettergi` 才看得全。
3. **华为上"断线重连"是全自动的、不要密码**：游戏弹「连接已断开 / 账号在另一处重复登录」时，

   到标题屏 → 点「点击进入」**(1122,999)** 就回世界，全程用已存 token、不出现账号密码框。
   ⇒ 用户说"你直接登吧"时这条路走得通；**一旦某一步冒出登录表单就立刻停手交回用户**。
